## One concrete next measurement method (proposal only)

Use existing Lean structured tracing, in **isolated exact-source diagnostic copies**, not a new profiler framework:

1. First run the uninstrumented original command under its original imports, options, script, shared budget and tactic defaults. Record pass/fail separately. Keep the original source as the acceptance check; do not accept a goal merely because an instrumented variant passes.
2. For one pilot call, enable scoped `trace.profiler=true`, `trace.profiler.threshold=0` and `trace.profiler.output=<private JSON path>` with heartbeat mode false. Lean's existing `Elab.step` node wraps `evalTactic`, has the source syntax reference and tactic-kind tag, and records inclusive start/stop wall time/result. Map ONLY the authored outer polytime/fun_prop/ppt node to the source span; generated/nested Aesop/FunProp calls must not be double-counted as independent authored calls. Keep profiler output enabled through export (diagnostic invocation/file-level options are preferable to an untested command-local output lifetime). Validate that export/span mapping once before expanding to this bounded representative set.
3. A second diagnostic pass can use `trace.profiler.useHeartbeats=true` and retain the node trace in counter units, with the same original maxHeartbeats. Pinned `withStartStop` reads `IO.getNumHeartbeats` directly; raw deltas divide by1000 for user-facing heartbeat units. Do not interpret heartbeat-mode export timestamps as wall milliseconds. Record execution mode (`Elab.async`) explicitly; if disabled for reproducibility, pair with an unchanged-limit baseline and qualify the scheduling difference.
4. Collect rule evidence in a SEPARATE trace run (`trace.Meta.Tactic.fun_prop`, `trace.aesop`; optional `trace.aesop.tree`, `.proof`, `.stats`). The valid Aesop action class is `trace.aesop`, not `trace.aesop.steps`. Keep attempts, successful local applications and final contributing proof distinguishable. An “applying theorem” trace may later backtrack; it is not automatically a fired rule in the final proof. Verbose trace overhead must not be reported as baseline elapsed cost.
5. Store source revision/span/imports, actual options, raw and converted units, node inclusive cost, success/failure/censored status and trace provenance. Nested node totals overlap. Hard interruption/missing final nodes remain missing/censored. No rule matches/encoder choices/proofs are cached by this proposal.

**Available cross-check / important trap.** Mathlib's tactic-form `#count_heartbeats <tacticSeq>` uses `runTacForHeartbeats`, disables async and counts raw heartbeats without resetting maxHeartbeats; it includes save-state/options/instrumentation overhead and logs only on success. It can cross-check a successful single-call pilot, not supply exact failure counts. The COMMAND form `#count_heartbeats in cmd` explicitly wraps `cmd` with `maxHeartbeats 0`; an inner explicit setter may override that, depending on nesting. Therefore never assume the command wrapper preserves the active acceptance budget. Repeated `!` forms restore tactic state between runs but are not a promise of cold global/process state. Do not use them to turn a fixed-budget failure into a successful acceptance result.

The older `profiler=true` output aggregates exclusive times by component/declaration/tactic syntax kind, not stable source call location; process/module wall time includes imports and other commands. Neither is per-call data. Current project Tactic/PolyTime/PPT files expose no dedicated trace-node boundary for classifier preparation versus matching, so that phase split is NOT automatically obtained by subtracting visible child nodes. Existing FunProp application nodes help explain candidates; an exact preparation-cost split would need separately authorized instrumentation, not this plan.
